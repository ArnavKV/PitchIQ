# Notes on the public version

This repo is the **public, code-only copy** of PitchIQ. The research project also has downloaded player and shot data and locally trained model files. Those are intentionally not part of this repository or its Git history.

The live app is at **https://pitchiq-demo.streamlit.app/**.

## What the public app uses

- **Match Explorer, Match Predictor and League Simulator:** optional real OpenFootball CC0 match records, fetched when the app runs. The match models train in memory; pretrained real-data model files aren't shipped.
- **Player Comparison, xG Predictor and Shot Simulator:** fictional data and models generated by the project. The public demo is not a source of real player statistics.
- **Champions League simulator:** a hypothetical bracket rather than an official current-season competition simulation.

Historical results and current fixtures depend on what's in OpenFootball at the time. Upcoming 2026–27 games are not verified outcomes, and the models haven't been independently validated on future results.

## Before publishing changes

From your **public** `PitchIQ` folder, check that the app runs and test the demo:

```bash
source .venv/bin/activate
PITCHIQ_DATA_MODE=demo python -m unittest discover -s tests -v
python -m compileall -q app.py pitchiq pages views scripts
```

Check the files before pushing:

```bash
git status --short
git add -A
python scripts/check_publication.py --tracked
git diff --cached --stat
```

Review the staged diff before committing. In particular, don't stage `data/`, `models/`, `.venv/`, downloaded caches, passwords or API keys. The publication check looks for some of these, but **passing it doesn't mean every file or the repository's entire history has been audited**. Only push when the tests pass and the pages have been tried manually.

`PUBLIC_MANIFEST.json` records hashes of the reviewed code-only files. Update it when published source files change (the project updater does this). CI also runs basic app tests and the publication check.

## If you're exporting from the research project

Don't push the research repository into this public one. Its earlier commits may include downloaded datasets, even if those files have since been deleted or added to `.gitignore`.

The research checkout has `scripts/export_public.py`, which creates a fresh code-only export without its prior Git history. Check the exported files and their third-party notices before publishing. For an existing public repo, make changes in that repo rather than merging histories.
